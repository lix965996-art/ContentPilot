# 功能修复记录

日期：2026-10-20。当前重点是 Bluesky、Mastodon 的图文编辑、审核、排期和 API 发布。

## 本轮已修复

- 原文或稿件实质修改撤销旧审核；人工审核和 AI 评审使用指纹与数据库版本条件写入，校验后发生的并发编辑也会返回冲突。创建排期、执行公开发布再次检查审核；保存工作草稿可以在审核前使用。
- VIEWER 不能调用会修改数据的质量评审、关键词提取；深度候选稿也返回完整指纹。审核前保存期间切换文章或版本，会停止旧操作。
- 实际质量评审与离线规则共用事实检查。金额、数字、日期、实体和简单否定冲突会列出证据；模型高分不能抵消冲突。规则降级明确要求人工复核。
- 工作台图片动作绑定文章、版本和请求代次，切换文章、返回旧文章或卸载后，旧成功、失败及 finally 不覆盖当前状态。
- 搜索选图和历史素材关联时安全下载本地，保留来源。图片服务支持已识别协议的 URL/Base64/Data URL、生成与编辑能力区分；不把所有自定义服务都当作相同协议。
- 发布包缺图会明确失败，前端显示具体原因；图片大小和总包大小受限，不再静默省略。
- 模型用量使用独立调用账本，覆盖生成、评审、关键词、推荐、图片、Embedding 和重试；删除稿件不删除用量。价格保留调用时快照，费用未知单独显示。
- 月度预算按已知花费和并发预留进行调用前拦截；缺少适用计价或存在未知费用时不会当作零成本放行。预留是本地估算，不能代替服务商硬额度。
- Bluesky 使用项目配置的出站代理。两个平台均验证了完整图文发布链路、回执丢失后的安全恢复，以及重复请求不产生重复帖子。
