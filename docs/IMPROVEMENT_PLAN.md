更新日期：2026-10-20。现有功能基线：[722ffe6](https://github.com/lix965996-art/ContentPilot/commit/722ffe63b139a674b155f18489c957654c39db05)。

## 1. 目标与范围

围绕 **Bluesky 与 Mastodon**，把已有内容适配、审核和日历排期扩展为“真实发布 → 互动采集 → 历史分析 → 模型评分 → 可解释推荐”的闭环。

大语言模型负责内容适配、关键词和语义分析；轻量监督学习模型预测互动表现；OR-Tools 处理锁定时间、账号间隔、禁发时段和跨平台错峰。模型选型以时间留出实验为依据，保留现有统计算法作为比较基线和冷启动方案。

优先本地功能完整性，不安排部署、演示包装、国内平台资质申请或框架重写。源码实际使用 Vue 3 + TypeScript + FastAPI + SQLAlchemy/Alembic；沿用已有架构与 ESLint/Prettier、Ruff 等检查。API 保持 `{ code, data, message }`，兼容现有 traceId。

| 完成层次      | 交付结果                                   | 可以说明的结论               |
| ------------- | ------------------------------------------ | ---------------------------- |
| A：产品闭环   | 两个平台发布、采集、历史记录与错误恢复连通 | 系统功能可用                 |
| B：训练与推理 | 可重复导出数据、训练、加载、评分和回退     | 已实现机器学习能力           |
| C：离线研究   | 冻结数据、时间留出、基线与消融、误差与区间 | 模型在指定数据范围的预测表现 |
| D：真实效果   | 独立设计的实际账号对照实验                 | 对实际发布时间策略的效果证据 |

A、B、C 分别验收。C 可以得出“没有稳定优于基线”的真实结论；训练代码不能代替效果证据。D 作为后续研究，不阻塞本次功能开发。

需要优先解决的三个数据问题：

1. metric_date 的日期粒度不足以确定“发布后 24 小时”；updated_at 也不能代替明确的采集时刻。
2. sync_schedule_feedback() 当前更新同一历史行，并读取当前稿件的标题、摘要和标签。训练必须使用实际发布时的冻结内容，避免后续编辑改变历史特征。
3. 当前反馈和推荐侧重有分母的互动率。两个平台的常规帖子读取接口提供互动计数，不能默认拿到曝光数；无曝光的真实计数需要独立进入学习路径。

以上是数据与学习能力的增强点，不应重复实现已有审核、outbox、并发保护和发布状态机。

## 3. 数据与预测目标

### 3.1 第一版目标：固定窗口互动计数

首选同平台、固定观察窗口的目标：

```text
I_24h = 点赞数 + 回复数 + 转发数
y = log1p(I_24h)
```

三个计数来自同次观测，并满足数据集的完整性规则。引用数独立保存，只有平台、实例和样本口径一致时才建立扩展目标；映射版本必须可追溯。

| 统一概念 | Bluesky 常规字段         | Mastodon 常规字段                    |
| -------- | ------------------------ | ------------------------------------ |
| 点赞     | likeCount                | favourites_count                     |
| 回复     | replyCount               | replies_count                        |
| 转发     | repostCount              | reblogs_count                        |
| 引用     | quoteCount，按可用性保存 | quotes_count，依实例版本与可用性保存 |
| 曝光     | 不假定常规帖子响应提供   | 不假定常规帖子响应提供               |

实现依据：[Bluesky getPosts](https://docs.bsky.app/docs/api/app-bsky-feed-get-posts)、[Mastodon Status](https://docs.joinmastodon.org/entities/Status/)。接入时再次核对响应、实例版本和权限；缺失字段不能默认变为真实零值。

互动率作为另一目标：可靠曝光分母对应曝光互动率；发布时粉丝快照可以形成“按粉丝数归一化的互动指标”，二者名称、分母和队列分别管理。采集当天粉丝数不能回填历史发布时粉丝数，粉丝归一化指标不能叫曝光率。

### 3.2 来源与使用范围

| 来源                     | 功能测试 | 研究训练/测试                            | 默认真实账号推荐             |
| ------------------------ | -------- | ---------------------------------------- | ---------------------------- |
| SIMULATED 合成数据       | 允许     | 仅验证代码，不形成真实效果结论           | 禁止激活为真实模型           |
| 自有账号 API 成熟观测    | 允许     | 时间、内容与口径合格后允许               | 通过适用范围与效果门禁后允许 |
| 手工真实记录             | 允许     | 补采集时间、依据与缺失标记，单列可信范围 | 经数据审计决定               |
| 有许可的目标平台公开历史 | 允许     | 核对抓取时间、内容、标签成熟性           | 需要目标平台和冷启动验证     |
| YouTube 等其他平台样本   | 允许     | 独立方法实验                             | 不直接宣称已验证跨平台迁移   |

ACCOUNT_HISTORY 等枚举不能单独证明数据可训练，还需核对真实/合成来源、采集时刻、窗口、文本覆盖和去重键。本次仅核对源码与数据结构，没有完成训练数据就绪审计，不预先宣布样本充足。

## 4. 实施任务与验收标准

### D-01 数据盘点与就绪审计（P0）

**拟新增**：scripts/audit_ml_data.py。

只读查询，按平台、来源、批次、账号数量和日期统计；统计正文覆盖、有效窗口、缺失计数、重复帖子、时区、成熟标签和时段支持。区分可训练数据与仅能做描述性分析的数据。

**产物**：var/reports/ml/ 下的一份 JSON；不把原始账号名、正文、令牌和个人数据写入 GitHub，不新增多份长期维护的报告。

**验收**：空库、合成数据、无采集时间、成熟观测四种情况均可运行；接受与排除的数量和原因完整；业务记录计数与内容不变；不确定的旧记录进入待核验，不自动补成 24h 标签。

### D-02 不可变观测与发布快照（P0，依赖 D-01）

**拟新增**：engagement_observation 表。保留 EngagementMetric 和旧页面兼容层，不直接替换旧表。

| 字段组 | 字段或约束                                                                       |
| ------ | -------------------------------------------------------------------------------- |
| 身份   | 平台、账号、排期、稳定帖子 ID；Mastodon ID 加服务器范围，Bluesky 使用规范 AT URI |
| 时间   | 平台发布时间、实际/计划采集时间、帖龄秒数、原始偏移；采用明确 UTC 存储约定       |
| 内容   | 实际发布快照或不可变引用、内容哈希、审核指纹、媒体数量、语言、特征版本           |
| 指标   | 可空点赞/回复/转发/引用/曝光/粉丝快照；字段可用性与口径                          |
| 状态   | API 来源、适配器版本、成功/失败、HTTP 状态、错误分类、重试次数；不保存认证头     |
| 幂等   | 同平台帖子、逻辑任务和窗口唯一；重试不产生重复有效训练样本                       |

成功观测保留为历史事实；更正以新记录或显式修订关联完成，不能覆盖旧值来伪造更早已知的结果。失败尝试可追踪；失败、无权限、删帖和真实零互动分别表示。

**验收**：MySQL/SQLite 新旧库升级均通过；同帖保留 1h、24h、72h 观测；重复任务幂等；发布后编辑不改变旧特征；未知字段经过数据库/API/UI 仍未知；迁移不伪造旧采集时间与成熟标签。

### D-03 两平台只读采集与恢复（P0，依赖 D-02）

**拟新增**：engagement_collection_service.py，以及平台适配器的只读采集能力。

回执确认后创建持久化采集意图，主要窗口为 24h，可选 1h/72h。复用 outbox 与调度器，增加独立采集处理器；采集恢复不能进入重新发帖路径。

Bluesky 通过官方帖子接口读取；Mastodon 从已配置实例读取。沿用代理、超时、身份和地址安全限制。只读取已授权或合法可读取的帖子，不通过批量发测试帖凑数据。

持久化 due_at、尝试次数与下次重试时间。429 按合理 Retry-After 退避；超时/5xx 有上限重试；401/403 明确连接或权限原因；404 保留帖子不可用，不写零互动。认证刷新仅沿用既有流程。

**验收**：两个适配器均覆盖正常、全零、缺字段、401/403、404、429、5xx、超时、重复派发和重启；核对实例及帖主身份；测试中外部写请求为 0，采集恢复过程发布器调用次数为 0。

### D-04 观察窗口与成熟标签（P0，依赖 D-02、D-03）

24h 标签规则进入配置与数据集清单。首版建议成功采集时帖龄位于 [24h, 24h + 15min]，保存实际帖龄，并比较 5/15/30 分钟容差的敏感性。

这是窗口近似：API 返回采集时点累计计数，24h15m 不能称为精确到秒的 24h。停机后在 30h 才取得的观测仍记为 30h；没有历史快照时不能事后恢复旧帖的 24h 指标。

**验收**：窗口内外、提前采集、跨日、时区、长停机和字段缺失均有边界测试；24h/72h 不混用；计数下降保留实际观测，不强制递增；排除记录有原因且仍可查看。

### ML-01 冻结数据集与防泄漏（P1，依赖 D-04）

**拟新增**：backend/app/ml/dataset.py、scripts/export_ml_dataset.py。

导出不可变数据与清单，记录源码提交、来源/批次、筛选、窗口、时区、接受/排除数量、拆分边界、标签版本和 SHA-256。

按稳定帖子 ID 去重。同帖的不同观测、重复导入与跨批次副本不能落入不同集合；相同时间戳分组；同一原文或活动的高度相关版本需要分组信息，并提供组隔离敏感性结果。

使用明确日历边界划分早期训练、中期验证、末期独立测试；验证选参，测试在方案冻结后使用。滚动验证提供多个时间折。发帖非等间隔序列，默认 TimeSeriesSplit 的行数间隔不能直接当作小时数。

每个训练截止点只接纳 observed_at 不晚于该点的成熟标签；历史特征只读取决策时已经观测到的信息。24h 标签需要按可用时间排除未成熟记录。缺失填充、归一化、TF-IDF、PCA、目标编码、检索库均由当折训练集建立。

**验收**：加入未来帖子、未来观测或未来粉丝快照，早期特征不变；同帖零交叉；默认排除合成数据和未知窗口；每个标签/特征可追溯原记录及可用时间；同一清单和种子生成相同数据集。

### ML-02 发布前特征与模型训练（P1，依赖 ML-01）

**拟新增**：backend/app/ml/features.py、training.py。先完成结构特征，再增加语义。

| 特征组 | 可用内容                                         | 边界                                    |
| ------ | ------------------------------------------------ | --------------------------------------- |
| 时间   | 候选小时/星期、周期编码、时区                    | 保留 UTC 与显示时区，做跨时区敏感性分析 |
| 内容   | 发布快照长度、标签/链接/图片数、语言、类型       | 与当前可编辑草稿区分                    |
| 历史   | 决策前 7/30 天已知发帖数、成熟互动统计、发帖间隔 | 不使用最终累计值或尚未观测的结果        |
| 账号   | 当时粉丝快照、支持量、冷启动标记                 | 当前粉丝数不能回填历史，缺失单列        |
| 语义   | 固定版本 Embedding 或训练集拟合的 TF-IDF         | 固定模型/维度，区分缺失和哈希降级       |

候选为 CatBoostRegressor、LightGBMRegressor，先用 CPU，控制深度、迭代和早停。增加依赖前验证 Python 3.12、当前 NumPy 与锁文件兼容性，不写未经测试的版本号；训练依赖独立锁定，普通 API 不强制安装整套训练工具。

第一版优先平台独立模型或显式分平台评估；不同平台原始计数不混成一个泛化成绩。新账号单独评估，避免只记住大账号与小账号差别。

**验收**：结构模型可训练、保存、加载、预测；相同输入结果在容差内一致；缺失、新类别、新账号不报错；训练不读取令牌；本帖结果计数不能作为特征；无正文或向量服务失败时模式明确。

### ML-03 比较实验与启用门禁（P1，依赖 ML-02）

在相同测试样本与标签上比较：

| 方法                            | 用途                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| 平台/账号历史均值、平滑计数均值 | 简单预测基线                                               |
| 小时/星期平滑统计               | 判断模型复杂度是否值得                                     |
| 当前 hybrid-v2/分层活跃度       | 保留时段排序；需要预测误差时仅在训练集建立评分到目标的映射 |
| CatBoost、LightGBM 结构特征     | 监督学习比较                                               |
| 选中模型 + 文本语义             | 语义增益消融                                               |

当前 0～100 活跃度分与预测计数不同量纲，不能直接当成同一个回归目标或随意平均。固定 20:00 可以是策略基线，但未实际发生的发布时间没有真实结果标签，不能硬算某帖“改到 20:00 的真实互动”。

主指标：log1p 目标 MAE。辅指标：原始计数 MAE、Spearman、按账号排序相关性、冷启动/已见账号分组、各平台与各时间折结果。常量标签或不足样本时返回不可计算并显示支持量。区间按账号或时间块重采样，不默认所有帖子相互独立。

启用 ML 需要数据审计、验证集稳定收益、方案冻结后的独立测试确认及分组检查。首版可配置“相对最强可用基线 MAE 降低至少 5%，差值区间支持改进”为工程门槛；这是项目选择，不是文献保证。样本不足估计区间时维持实验状态。

没有统一科学及格样本量。可用“同平台成熟帖约 300 条、跨度约 8 周、每验证折约 50 条”作为是否值得尝试的审查起点；启用仍由分组覆盖、学习曲线和区间决定。低于起点也可验收训练管道，不能承诺个性化精度。

**验收**：输出全部基线、失败模型、排除原因、种子、参数、耗时、硬件和数据哈希；测试不参与调参/选型；预处理与检索遵守时间边界；模型不优于基线时也完整记录并显示真实结论。

### APP-01 接入候选评分与回退（P1，依赖 ML-03）

**拟新增**：ml_prediction_service.py。通过 semantic_schedule_pipeline.py 的候选评分入口接入，保留 build_candidates() 与 CP-SAT。HTTP 请求只做有限批量推理，训练在独立命令或后台任务中执行。

同次决策按 decision_at 冻结账号历史。未来候选只改变已知时间特征，不能假定未来粉丝、互动或新帖子。只有发布时信息的数据仅验证临发前预测；提前数天排期的适用性另行评估。

推荐输出保存评分模式、模型/特征版本、目标/窗口、decisionAt、数据截止点、来源平台、支持量、适用范围和 fallbackReason。校准到排期评分的参数仅用训练/验证数据确定。

模型缺失、哈希异常、特征不兼容、数据不适用、超时或非有限数值时，回到原统计方法并说明原因。回退不能绕过审核、内容指纹、锁定时间、权限和派发状态；切换算法不直接更改已有排期。

**验收**：逐项异常注入可恢复；无模型环境可启动；原有硬约束和幂等测试通过；快照追溯原版本；批量候选数有上限，记录 P50/P95、硬件和候选规模后设实际性能预算。

### APP-02 界面解释与模型管理（P1，依赖 APP-01）

复用推荐页、数据页、平台账号页和设置页，避免重复菜单。

### QA-01 全链路与故障验收（P1，贯穿全部任务）

隔离数据库与平台 HTTP 传输，执行真实业务和适配器代码，覆盖“原文 → 生成 → 保存 → 审核 → 排期 → 回执 → 采集 → 成熟观测 → 数据集 → 模型评分 → 新推荐”。训练测试使用的合成模型带测试标记，真实模型入口不得激活。

普通测试真实平台写请求和付费模型请求均为 0。真实账号只读验证在有效配置后单列；Mastodon 凭证由用户在本机填写，不从聊天截图提取旧令牌。

| 场景                   | 必须断言                           |
| ---------------------- | ---------------------------------- |
| 两平台分别成功         | 帖子 ID、内容快照、观测来源一致    |
| 发布成功但响应丢失     | 核验原帖；采集恢复不多发一帖       |
| 派发失败或重启         | 业务数据与意图保留，恢复幂等       |
| 采集超时/限流/失效授权 | 原因、上限和恢复明确，不伪造零     |
| 零互动且无曝光         | 零可用于计数任务，互动率未知       |
| 后续编辑               | 旧特征不变，新稿按既有规则撤销审核 |
| 标签不成熟或不完整     | 排除并说明，不静默填补             |
| 同帖跨批次/窗口        | 不重复、不跨集合泄漏               |
| 模型或特征异常         | 回退统计，审核和硬约束不变         |
| 时区与提前排期         | 截止点和显示一致，不能读取未来状态 |

新测试纳入现有 `.\contentpilot.ps1 test`。MySQL/SQLite 均验证迁移与关键业务；测试数量以实际结果更新，不硬编码数量。

## 5. 目录、模型产物与交付

拟新增结构：

```text
backend/app/ml/                  数据集、特征、训练、评估与模型清单
backend/app/services/            采集服务、推理适配，沿用服务层
scripts/                        审计、导出、训练、评估命令
var/datasets/ml/<dataset-id>/    本地冻结数据与清单，不进 Git
var/models/<model-version>/     模型、特征清单、评估摘要，不进 Git
var/reports/ml/                 实验与诊断结果，不进 Git
docs/IMPROVEMENT_PLAN.md         统一任务与验收入口
```

模型清单保存算法、目标、平台、数据/特征版本、训练截止时间、依赖、评估和哈希。优先使用 CatBoost/LightGBM 原生格式与 JSON 配置；不直接加载不可信 pickle/joblib。激活前核对本机训练来源、路径和哈希。

每次训练生成新版本，完成后原子激活，保留上一已验收版以便回滚。只保留被引用数据、当前/上一版模型和必要摘要；过期产物按清单清理，数据库、令牌、上传素材、真实回执和在用研究证据保留。

每个任务交付：编号、修改文件、迁移影响、实际命令、关键断言、通过/失败/跳过项。更新已有修复报告的本批章节，不为每次运行新建长篇 MD。

## 6. 顺序与完成边界

```mermaid
flowchart LR
    A[D-01 数据审计] --> B[D-02 观测与快照]
    B --> C[D-03 两平台采集]
    C --> D[D-04 成熟标签]
    D --> E[ML-01 冻结与时间切分]
    E --> F[ML-02 特征与训练]
    F --> G[ML-03 比较与门禁]
    G --> H[APP-01 候选评分]
    H --> I[APP-02 解释与管理]
```

1. 先实现数据与采集。真实数据持续积累，代码开发不需要等待每个 24h 窗口。
2. 完成导出、训练、验证和回退。少数据时用隔离合成数据验收程序，合规公开数据做独立方法实验。
3. 同平台真实数据满足要求后验收默认模型；不优于基线则保持统计推荐与实验模式。
4. 补界面和全量回归；部署、演示包装与国内平台扩展不插入主线。

预先记录训练预算、参数搜索范围和指标。不得为追求预设涨幅无限调参；查看测试后改变研究假设，后续实验需新的独立留出范围。

## 8. 最终验收清单

- [ ] 两平台回执关联只读观测，失败与缺失有明确状态。
- [ ] 采集持久化、可重试、重启恢复，恢复不会重复发帖。
- [ ] 内容快照不可变，未知曝光与真实零互动正确表示。
- [ ] 24h 标签遵守窗口，旧累计数据与 72h 不混入。
- [ ] 数据可重建、可追溯，来源明确，未来信息不影响历史特征。
- [ ] 统计基线、CatBoost、LightGBM 使用一致样本和时间规则，语义有消融。
- [ ] 数据不足、无模型、模型异常均回退，原审核和硬约束通过。
- [ ] 页面显示来源、版本和范围，不显示未经验证的准确率或流量承诺。
- [ ] 权限、文件来源、哈希可核验，私有数据与产物不进 GitHub。
- [ ] 全量检查记录实际结果，外部条件不足单列，未完成不标完成。
